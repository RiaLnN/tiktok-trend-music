# TikTok Trends Bot

Telegram-бот на **aiogram 3+**, который находит трендовые треки в TikTok
(через API [tiktok-scraper7](https://rapidapi.com/tikwm-tikwm-default/api/tiktok-scraper7)
на RapidAPI) и присылает их аудио прямо в чат — вместе с превью видео, в
которых эти треки звучат. Все параметры поиска настраиваются индивидуально
под каждого пользователя через `/settings`.

## Возможности

- 🔑 **Ключевые слова** — можно добавить несколько; бот опрашивает API по
  каждому и объединяет результат в один список треков
- 🌍 **Страна** — фильтр по региону TikTok (код ISO, например `US`, `RU`)
  или без ограничений
- 🕒 **Период публикации** — сутки / неделя / месяц / 3 месяца / полгода /
  всё время
- 📊 **Сортировка** — по релевантности или по популярности (лайкам)
- 🔢 **Количество треков** и **видео-источников на трек** — тоже настраиваются
- 🎵 Треки дедуплицируются: если один и тот же трек встретился в нескольких
  видео, он присылается один раз, а под ним — обложки всех найденных видео
  со ссылками и статистикой (просмотры/лайки)
- ⚙️ Настройки у каждого пользователя свои и сохраняются между перезапусками
  бота (JSON-файл `data/user_settings.json`)

## Установка

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

Заполните `.env`:

- `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather)
- `RAPIDAPI_KEY` — ключ RapidAPI с активной подпиской на
  [tiktok-scraper7](https://rapidapi.com/tikwm-tikwm-default/api/tiktok-scraper7)

Запуск:

```bash
python main.py
```

## Команды бота

| Команда                  | Что делает                                              |
|---------------------------|----------------------------------------------------------|
| `/start`                  | приветствие и список команд                              |
| `/help`                   | краткая инструкция                                        |
| `/settings`                | меню настроек поиска                                       |
| `/trends` (`/get_trends`)  | запустить поиск и получить треки по текущим настройкам     |

## Структура проекта

```
config.py                   # чтение .env / переменных окружения
main.py                     # точка входа, сборка бота

models/
  settings.py                 # UserSettings + enum'ы + справочники (регионы, периоды, сортировка)
  tiktok.py                    # Track, VideoSource — доменные модели результатов поиска

services/
  tiktok_api.py                 # тонкий клиент tiktok-scraper7 (GET /feed/search)
  trends_service.py             # оркестрация: поиск по ключевым словам, пагинация,
                                 # дедупликация треков, параллельное скачивание аудио
  audio_downloader.py           # скачивание файла по прямой ссылке

storage/
  settings_repository.py        # JSON-хранилище пользовательских настроек

handlers/
  start.py                      # /start, /help
  settings.py                   # /settings и всё дерево инлайн-меню
  trends.py                     # /trends — основной сценарий (поиск -> скачивание -> отправка)

keyboards/
  callback_data.py               # CallbackData-фабрика для инлайн-кнопок
  settings_kb.py                  # сборка клавиатур меню настроек

states/
  settings_states.py             # FSM-состояние для ввода нового ключевого слова

utils/
  constants.py                    # константы (пресеты кнопок, лимиты)
  formatting.py                    # безопасные имена файлов, HTML-подписи, формат чисел
```

Каждый слой не знает о деталях соседних: `services` ничего не знает про
Telegram, `handlers` ничего не знают про HTTP, `storage` можно заменить на
SQLite/Postgres, просто сохранив тот же интерфейс `get`/`save`.

## ⚠️ Важное про параметры `/feed/search`

У tiktok-scraper7 нет открытой публичной документации со списком всех
значений параметров (страница RapidAPI требует авторизации), поэтому
значения `publish_time` и `sort_type` в `models/settings.py` заданы по
аналогии с фильтрами родного поиска TikTok (Дата публикации / Сортировка),
которые эта API прокси­рует:

- `publish_time`: `0` — всё время, `1` — сутки, `7` — неделя, `30` — месяц,
  `90` — 3 месяца, `180` — полгода
- `sort_type`: `0` — по релевантности, `1` — по лайкам (популярности)
- `region`: двухбуквенный код страны (ISO 3166-1 alpha-2), пусто — без
  ограничений

Это соответствует и вашему исходному MVP (`publish_time=7`, `sort_type=1`
для поиска трендов за неделю по лайкам). Если на практике конкретные
значения у вас на тарифе RapidAPI ведут себя иначе — поправить нужно только
в одном месте: подписи и enum'ы в `models/settings.py`, сам список
параметров запроса — в `services/tiktok_api.py`. Остальной код их не
касается.

## Хранение данных

- Настройки пользователей: `data/user_settings.json` (создаётся автоматически)
- Аудио скачивается во временную папку `data/audio/` и удаляется сразу
  после отправки в Telegram

## Возможные доработки

- Заменить JSON-хранилище на SQLite/Postgres при росте числа пользователей
  (интерфейс `SettingsRepository.get/save` специально для этого узкий)
- Добавить APScheduler/cron для автоматической регулярной рассылки трендов
- Кэшировать уже отправленные треки, чтобы не дублировать их при повторных
  запусках `/trends`
- Добавить поддержку нескольких активных подборок (пресетов настроек) на
  одного пользователя
